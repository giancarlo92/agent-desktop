description: Reference for the record command, which streams a person's own clicks, drags, typing, choices, key presses and scrolls to a JSON Lines file with the accessibility identity of every target.
---

`record` watches what a person does in a window and writes one JSON line per action. Each line names the element the action targeted by its role, name and native id, the same evidence `find` and the ref commands use, so a recording can be replayed with ordinary commands. `record` only observes: it sends no input and takes no interaction lease. It runs on Windows; macOS and Linux return `PLATFORM_NOT_SUPPORTED`.

## record

```bash
agent-desktop record --out FILE [--app NAME | --window-id ID | --display ID] [--stop-file PATH] [--max-duration-ms MS] [--include-injected] [--video | --video-out FILE.mp4]
agent-desktop record start [--out FILE] [--app NAME | --window-id ID | --display ID] [--max-duration-ms MS] [--include-injected] [--video | --video-out FILE.mp4]
agent-desktop record stop [--id ID] [--timeout-ms MS]
agent-desktop record status
```

The session also stops on Ctrl+C or Ctrl+Break in the console that runs it. Actions in that console and in the recorder's own process are never recorded. Start the demonstration after the `recording_ready` line appears in the file; actions before it are not seen.

The envelope is printed once, when the session ends:

```json
{ "version": "2.6", "ok": true, "command": "record",
  "data": { "out": "demo.jsonl", "format": "agent-desktop.recording/v1", "events": 14,
            "duration_ms": 8410, "stop_reason": "stop_file" } }
```

`stop_reason` is `interrupted`, `stop_file`, `max_duration` or `indicator`. With a video, `data.video` (and the `recording_stopped` line) gives `path`, `width`, `height`, `frames` and `offset_ms`: when the first frame was taken on the recording's clock, so an action at `t_ms` is at `t_ms - offset_ms` in the video. The video shows the area as it was placed when the session started, at 12 frames per second, with the pointer. If the video fails midway, the recording is kept and `data.video` is absent.

## record start and record stop

An agent or a tool that cannot hold a process open records in the background:

```bash
agent-desktop record start --window-id w-123 --video     # returns at once, after recording_ready
agent-desktop record stop                                 # stops it and returns the summary
```

`record status` lists the background sessions (`id`, `state` (`recording` or `ended`), `scope`, `elapsed_ms`, `out`, `video`) and the displays with their numbers, so a person or an agent can see what is recording and choose a display. `start` shows the indicator unless `--no-indicator`. `start` takes the same scope and video flags as `record` and returns `{ "id", "state": "recording", "pid", "out", "video" }` once the session is observing input. Without `--out`, the events go to `recordings/<id>.jsonl` under the agent-desktop state directory (`~/.agent-desktop`, or `AGENT_DESKTOP_HOME`). `stop` stops the only running session, or the one `--id` names, waits up to `--timeout-ms` (default 60000) for it to finish its video, and returns `{ "id", "state": "stopped", "out", "events", "duration_ms", "stop_reason", "video" }`. Through `agent-desktop mcp` they are the tools `desktop_record_start` and `desktop_record_stop`; the foreground `record` is not a tool, because it holds the call until the session ends. The session runs as its own process, detached from the caller (and from the caller's job when the job allows it), so it outlives the call that started it. A client that kills every process it started when a turn ends (`codex exec`, one process per turn) ends the session with it; `record stop` then reports that it ended early, and the video, a fragmented MP4, plays up to that moment. Interactive clients keep their MCP server between messages, so the session lasts until `record stop`.

## The recording file

The first line is `recording_started` with the session parameters, then `recording_ready`, then one line per action, and `recording_stopped` last. Every action line has `kind`, `t_ms` (milliseconds since the session started), `window` (`id`, `title`, `app_name`, `pid`, `bounds`, so a positional action can follow a window that moved, `path`: the app's executable, read while it runs, so a replay can start an app the demonstration closed, and for a browser window `url`: the address bar's text) and, when UI Automation answers, `element` (`role`, `name`, `native_id`, `class_name`, `bounds`, `help_text` such as a field's placeholder, and for a form field with none of these, `label`: the nearest short text before it). A press on an unnamed icon or caption inside a button is reported on the button, up to six `ancestors` with a name or native id, and `match_count`: how many elements in the same top-level window share the element's control type and identity. A `match_count` above 1 means the identity alone is ambiguous on replay and the ancestors are needed.

## Limits

- A key that composes with a dead key (an accent) is missing its accent in `typed`; `value` is exact when the control exposes one.
- A surface with no UI Automation provider records the `point` and `window` without an `element`.
- Actions in an elevated window are only identified when the recorder runs elevated too.

## Replaying a stroke

A drag on a canvas (a letter or a shape drawn with a pencil) names no element, so it is replayed with its `path` through `stroke`, which holds the left button down at the first point, moves through every point at its time and releases at the last. It runs on Windows and needs `--headed`.

```bash
agent-desktop --headed stroke --path "100,200;140,200;140,260"
agent-desktop --headed stroke --path-file stroke.json --offset=-12,30
```

`--path` takes `x,y` pairs separated by `;`, or a JSON array of `[x, y]` or `[x, y, ms]` points, which is the shape of a recorded drag's `path`. `--path-file` reads the same formats from a file. Points without a time are `--step-ms` apart (16 by default). `--offset` adds to every point, for a window that moved since the recording. A stroke has 2 to 4096 points and lasts at most 60 seconds.
